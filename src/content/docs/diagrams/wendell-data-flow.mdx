voice conversation and general reasoning, appointment booking, and caller memory. The
phone bridge is the only service exposed through ngrok; neither Hermes nor Calendar
has a public route.

## Primary call path

A caller reaches the Australian Twilio number. Twilio posts the incoming-call
webhook through ngrok, receives Media Streams TwiML, and then sends bidirectional
G.711 audio through the same tunnel to the Wendell bridge on loopback port `8787`.
The bridge applies the caller allowlist, owns per-call state, and records calls under
the isolated Wendell profile.

## Voice and general questions

The bridge exchanges audio, transcripts, and commentary with OpenAI GPT-Live. When
a caller asks a general question, the bridge delegates it to the isolated
`wendell` Hermes API route. That profile has API toolsets disabled, memory disabled,
and no route to Paul's default Hermes profile.

## Caller memory

Caller continuity is a third path out of the bridge, separate from both the voice
model and the reasoning profile. After the allowlist check the bridge recalls from a
Hindsight bank keyed to the trusted Twilio `From` number, and it can write back only
through the same scoped bank. GPT-Live never sees that bank, and the `wendell` profile
still has memory off.

A save needs the caller to say something explicit, then a second explicit
confirmation: the bridge reads the proposed value back and stores it only after the
caller agrees. PINs, passwords, tokens, verification codes, card details, and call
transcripts are refused.

## Appointment booking

Booking dialogue uses a separate narrow backend inside the bridge. The backend uses
the OpenAI Responses API to collect structured details, Nominatim to validate an
Australian address, and Google Calendar to read free/busy periods. Calendar events
are written only after the caller hears the prepared summary and explicitly confirms
in a later utterance.

## Trust boundaries

The public edge terminates at the bridge. Twilio and ngrok cannot directly call the
Hermes profile, Nominatim, Google Calendar, or the caller memory service. PIN digits
are consumed locally, and the trusted callback number comes from Twilio metadata
rather than from spoken input.

Caller memory is scoped by that same trusted `From` value: the bridge derives an
opaque bank name, recalls only that bank, and requires the caller's separate spoken
confirmation before writing. Nothing in the bank is exposed to the voice model or
the `wendell` Hermes profile.
